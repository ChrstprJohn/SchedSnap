# UniToolbox

UniToolbox brings practical tools for university students into one extensible platform. The landing page introduces the platform and links to independent services; it is not branded exclusively around schedule wallpapers.

The first service turns a registration-form image into a mobile schedule wallpaper: choose a template, upload the form, verify the extracted details, then download a PNG. Gemini extraction stays behind a server API. Manual entry is available when extraction fails. Students can correct subjects, times, weekday meetings, and rooms. All edits remain in memory; uploads are not stored. A native browser confirmation protects unsaved changes when refreshing or leaving the page, without a persistent refresh-reset note.

Current output is 1080 × 2400 portrait. The collection has 62 templates: 20 Chiikawa-inspired Little Friends editions, 20 animal mascot editions and six editable pattern templates appear before the 16 original general templates inspired by the supplied reference images. Bold, soft, and everyday editions offer independent wallpaper personalities while retaining the established white/slate application. The student journey remains choose, review, then download.

The mascot editions pair transparent animal cutouts with uniform Canvas backgrounds. No timetable, student details, heading, or edition label is baked into the animal art; the renderer supplies them separately. All templates share a readable Class Schedule title, separate growing day cards, and consistent time and subject columns. Circular M, T, W, TH, F badges stay centered within their day; times include minutes and AM/PM and center beside each meeting. Actual schedules preserve every meeting, keep subject names on one line, shrink them by up to 20%, then truncate with an ellipsis, and omit empty days. Body type fits within 28–42px. Mascots retain a fixed 620px maximum occupied dimension in a reserved footer; schedules that still overflow block export. Gallery examples show Monday–Friday with one neutral subject and time each, and images load near the viewport. Device, tablet, and orientation controls are outside the current scope.

The interface should be clean, white, and concise. A separate step indicator is omitted; Back, Continue, and Download guide the flow. A shared sticky logo header appears across pages, transparent at the top and white while scrolling. Template previews open in a modal. Classes contains image import and class editing, followed by Preview. Download contains the actual wallpaper, PNG download, and optional customization. Back returns to the previous step, and the Classes heading stays Add your classes while editing, and the design heading always stays Choose a design. The class toolbar shows the wallpaper title with a pencil button for inline editing; changes carry through designs, previews and PNG exports.

Course codes lead each meeting in large bold type, with smaller centered subject names below and a separate centered room column. Missing codes fall back to a readable subject name. The final screen includes an optional appearance disclosure grouped into Wallpaper, Day containers, and Schedule Text: background, fill, border and text colors, shape, border/fill toggles, plus DM Sans, Geist, Poppins, Inter, Roboto, Open Sans, Montserrat, Lato, DM Serif Display or Georgia. Choices apply live to the preview and PNG. Phones keep a small preview visible while customizing and expand its strip only while stuck. Color labels are concise and aligned in rows; fill and border checkboxes mute and disable their color palettes. Class headers use the subject and course code with delete and chevron controls. Add class sits below the list. Inline validation focuses the first invalid field when Continue is pressed. The sample contains five different classes, one meeting each Monday–Friday. Image replacement uses Change image and the primary Import classes action. Clicking the image opens a zoomable dialog. Filenames are omitted. Upload image opens the file picker directly; Back to classes preserves edits, while Cancel after manual or sample entry returns to the starting choices. Desktop uploads support drag and drop. Selected-image import has Cancel, which clears the pending image and preserves the existing classes; a short inline warning explains that importing replaces current classes and edits. Phones hide the design preview and use a taller, centered upload area that adapts to the available screen height; Cancel and Preview use equal-width buttons. The data-use note sits below the image on the left, with actions on the right. Existing classes remain until an import succeeds. Control-wheel zooms enlarged previews. Reset appearance restores the original preset. Settings stay in page memory. Existing schedules appear in the template modal; otherwise neutral weekday examples show the same code/subject/room hierarchy through the same renderer.
